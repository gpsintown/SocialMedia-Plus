# Prepare a complete LinkedIn week

Use for WEEK, REWORK and ASSET. Read the master guide, settings, private context/voice/editorial policy and relevant claims. Use `content-strategy`, `social`, `linkedin-content`, `smp-council` and Humanizer as needed. The user's selected host performs reasoning; the CLI stores records.

## Evidence and briefs

1. Resolve an explicit Monday–Sunday range in the user's configured timezone. If omitted, choose the next calendar Monday and pass its date explicitly to `plan-week --start`. Display the range. Inspect `content list`, `action list`, recent reports and earlier drafts. Resume the requested batch and preserve completed work; do not create a second week with identical items.
2. Reuse a recent complete weekly review. Otherwise review actual available measurements, prior posts, user edits and conversations. Refresh only through permitted sources/tools. Record source and observation time; unavailable or stale metrics remain labelled. A local scheduled state is not live queue verification.
3. Read `relationship coverage` and relevant relationship history. Distinguish connections, observed incoming followers, followed accounts and unknown memberships. A connection export is not a follower roster. Do not claim comprehensive coverage from a sampled list.
4. Select a manageable rotation. Each brief states reader, practical point, evidence, supported personal contribution, pillar, format, intended asset and why it is distinct from recent work. A reasoned opinion is welcome; forced controversy and invented emotion are not required. Treat posting windows and cadence as hypotheses.

## Draft, review and assets

Write each full draft in the user's voice. Use a personal example only when sourced; label illustrative examples clearly. The normal formats are text, image, PDF document and native article where supported. An article can replace a slot rather than add workload. Other platforms remain future integrations.

For substantial drafts follow [the council](council.md), using the same frozen artifact and context for every lens. Reconcile material objections, apply Humanizer, then compare facts and meaning with the source. Short edits may use compact factual/voice review. Record the actual degree of reviewer independence.

Create actual final assets. For a document carousel, write the narrative, render the PDF, inspect each page at mobile scale, and correct clipping/order/legibility. For imagery, use the host's available image tools when helpful. Keep editable sources, final exports, alt text and provenance. Never fabricate client screenshots, analytics results, certificates or engagement counts. If a required tool/asset is unavailable, the item remains incomplete.

## Register and present

Use `python3 scripts/smp --help` and subcommand help for exact options. Register text using `content add` or `content revise`; use `content format`, `asset add`, `content slot` and `content route` for the final format, assets, offset-aware time and verified route. Retain immutable versions. A future slot in SQLite is a proposal, not a scheduled post.

Run `python3 scripts/smp plan-week --start YYYY-MM-DD` using the resolved actual date. Save a private batch report that links every exact item ID/version, full text, final assets, destination, route and dated local time/timezone. Separate ready items from specific remaining gaps. Return this whole finished batch in one reviewable result.

WEEK does not publish or schedule. A later SCHEDULE instruction covers only the unchanged completed batch already presented. If a revision changes text, asset, time, destination or route, bind any approval to the revised fingerprint. Do not infer that local revision cancels an existing remote queue item.
