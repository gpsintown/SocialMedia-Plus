# Combined editorial council

Follow [the shared council workflow](../../../workflows/council.md). Read the `council-review` and `llm-council` entries as contributions to this one review; do not run two full councils for one artifact.

Freeze the exact draft, source evidence, audience brief, shared user context and relevant claim limits. Give the identical packet to a skeptical practitioner, voice editor, busy reader, fair contrarian and relationship/reputation reviewer. Keep first passes separate using available supported agents and fresh-context waves. Do not hardcode tool/model names or start another provider API.

Use anonymous challenge when useful and synthesize based on evidence rather than votes. Preserve a fair personal opinion, supported strengths and strongest unresolved dissent. Role diversity is not model diversity. If only one active model can review sequentially, label that limitation plainly.

Deliver revised work, specific accepted/rejected edits and material unknowns. Save actual review provenance. A council is editorial reasoning, not an external action permission or accuracy guarantee. Short comments normally need only compact context/fact/voice review.


## Shared context and host

Before strategy, public writing, language edits, replies or review, read the private `profile/context.md`, `profile/voice.md`, `profile/editorial-policy.md` and relevant `profile/claims.json` records. Never treat templates as personal evidence. Use the user's selected Codex or Claude host model and exposed tools. The local CLI stores records; it is not a remote publisher or LLM. Current user instructions determine authorization, and no previous user's permission is included.
