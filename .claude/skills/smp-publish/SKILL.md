# Publish an exact item

Follow [publishing](../../../workflows/publish.md). Inspect `content show`, final assets, `content check`, action history and publishing authority. Complete all reviewable details before recording approval from the actual current user instruction. Reuse unchanged authorized work; do not invent permission or broaden a batch.

The fingerprint binds content, assets, destination, route and time. Choose a route with `content route` before `content approve`. An active remote item must be reconciled before a route change or requeue. `action prepare` creates only a local handoff; it does not publish.

Use a verified available native browser/connector route, inspect the sender and format-specific composer, submit once and verify the actual result. API setup does not automatically provide writing, article or future-scheduling support. Record observed remote references and distinguish scheduled from published. An ambiguous write stays uncertain until inspected and reconciled; never switch transport as an automatic retry.

Keep a manual handoff complete when execution is unavailable and state what remains pending. No success claim without a receipt, and no assumption that a local revision cancels a remote post.


## Shared context and host

Before strategy, public writing, language edits, replies or review, read the private `profile/context.md`, `profile/voice.md`, `profile/editorial-policy.md` and relevant `profile/claims.json` records. Never treat templates as personal evidence. Use the user's selected Codex or Claude host model and exposed tools. The local CLI stores records; it is not a remote publisher or LLM. Current user instructions determine authorization, and no previous user's permission is included.
