# Bounded daily conversations

Use for ENGAGE, NETWORK, DISCOVER, RECRUITERS and REPLIES. Plus modes also read their own workflow and `config/engagement-plus.json`. Read the guide, command scope, private context/voice/editorial policy, relevant claims, discovery settings and recent interaction history before preparing public text.

## Authorization and discovery

A current explicit live invocation permits contextual comments/replies in this session. Record the user's exact command and time in the private session report, or reference its saved dashboard request. Reading examples, installing a listener or a timer tick provides no new social permission. Preview researches and drafts only. Regular modes do not authorize DMs, invitations, applications, follows or bulk likes.

Use the configured duration (30 minutes by default) and a bounded review budget. Start from actual unanswered replies and useful ongoing conversations. Check `python3 scripts/smp daily`, `relationship coverage` and appropriate `relationship due` filters. NETWORK includes connections and observed incoming followers; a stable profile ID owns their overlapping membership, history and cooldown. Consider `relationship due --membership follower --exclude-membership connection` alongside the normal queue when evidence supports it. An outgoing Following button does not establish incoming follower status; incomplete collections must not imply an unfollow.

Select targets using observed professional relevance and actual current discussions. Read the post and its parent thread, author identity, observation time, existing user interaction and any external claim needed for the response. A keyword match, large reaction count, profile visit or inferred identity is insufficient. Use only an available authorized browser/connector; the preferred route reuses the current signed-in Chrome session through host tools. Do not scrape hidden APIs, extract cookies, bypass challenges or manufacture a browser capability.

## Draft and execute

For each candidate, identify a particular useful contribution: a sourced example, practical distinction, relevant experience supported by claims, thoughtful question or fair disagreement. Skip generic praise, unnecessary repetition and unrelated hiring pitches. Keep private career goals, analytics and confidential details out of public comments. Use a compact factual/context/voice check and Humanizer where useful. Do not run five agents for every short comment.

Check current relationship history, target and cooldown before sending. Prepare the exact local action with `action prepare --kind comment` or `--kind reply`, using `--authority native_linkedin`, exact `--target`, `--relationship` when known, `--response-file` and `--context-file`. The context file must preserve the actual current authorization, observed source/thread context and selection reason. Run `action check ID` immediately before the single authorized submission. Local preparation alone sends nothing.

Verify the actual sender and target, submit once, and inspect the resulting visible comment/reply. Record `action receipt ID --state confirmed --evidence ...` with the actual remote URL/ID where available. If outcome is ambiguous, record `uncertain` and inspect before retrying. A successful click or emptied composer is not enough to claim delivery. Respect stop requests and account challenges immediately.

Use CLI interaction/relationship commands for confirmed participation and next review dates; do not invent membership, attention or reciprocal interest. Stop new submissions at the deadline, finish recording the current attempt and save the report. Report actual confirmed actions, useful deferred candidates, uncertainties and next steps. A relevant session with zero sends is valid; never create an engagement quota.
