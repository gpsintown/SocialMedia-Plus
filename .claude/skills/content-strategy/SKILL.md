# Personal content strategy

Read the user's private professional brief, goals, intended readers, claims, recent content and available review outcomes. Distinguish topics supported by personal evidence from explanations grounded in external sources. Keep credentials, titles, contribution and estimates within their actual evidence.

For each brief state the reader, concrete problem or tradeoff, useful point, available evidence, why the user can contribute and the format that best explains it. A generic example: explain a recurring handover mistake using a clearly hypothetical checklist; do not present it as a remembered client incident.

Choose a manageable set of pillars and vary actual questions/angles. Reusing a topic needs a new contribution rather than a paraphrased opening. Private geography/career choices are audience filters only when the current user has supplied them. Do not infer local experience or eligibility.

Use [weekly](../../../workflows/weekly.md) for complete preparation and [analysis](../../../workflows/analyze.md) for learning. Treat reach/frequency advice as a hypothesis and useful conversations as observed outcomes. Avoid claims about a private algorithm based on a repository formula.

## Shared context and host

Before strategy, public writing, language edits, replies or review, read the private `profile/context.md`, `profile/voice.md`, `profile/editorial-policy.md` and relevant `profile/claims.json` records. Never treat templates as personal evidence. Use the user's selected Codex or Claude host model and exposed tools. The local CLI stores records; it is not a remote publisher or LLM. Current user instructions determine authorization, and no previous user's permission is included.
